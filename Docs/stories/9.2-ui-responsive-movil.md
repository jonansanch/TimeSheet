# Story 9.2: UI Responsive — Adaptación de Pantallas para Móvil

Status: todo

## Story

As a empleado de KPG,
I want usar la aplicación de timesheet desde mi celular con la misma comodidad que en el escritorio,
So that pueda registrar mis horas, consultar mi historial y ver el dashboard sin necesidad de hacer zoom ni desplazarme horizontalmente.

## Acceptance Criteria

1. **Given** un dispositivo móvil con pantalla de 360–414px de ancho, **When** el usuario navega por cualquier pantalla, **Then** no aparece scroll horizontal **And** todos los elementos interactivos (botones, campos) tienen al menos 44×44px de área táctil.

2. **Given** el formulario de registro de horas (`KpgShiftForm`) en móvil, **When** el usuario lo abre, **Then** los campos se apilan verticalmente en una sola columna **And** los selectores de hora (`MudTimePicker`) abren un modal full-screen compatible con teclado numérico táctil.

3. **Given** la pantalla "Mis Registros" en móvil, **When** la tabla tiene más de 3 columnas, **Then** las columnas secundarias (Modalidad, Lugar, Recurso) se ocultan **And** se puede expandir una fila para ver el detalle completo.

4. **Given** el menú lateral (`NavMenu`) en móvil, **When** el usuario abre la app instalada, **Then** el drawer se muestra colapsado por defecto **And** el botón de hamburguesa en el AppBar lo abre y cierra correctamente.

5. **Given** las tarjetas del dashboard en móvil, **When** se renderizan, **Then** se apilan en una sola columna (no en grid de 2–4 columnas) **And** los números y textos son legibles sin zoom.

6. **Given** cualquier diálogo (`MudDialog`) en móvil, **When** se abre, **Then** ocupa al menos el 95% del ancho de pantalla **And** no queda cortado por los bordes.

## Tasks / Subtasks

- [ ] **T1 — Viewport meta tag** (AC: 1)
  - [ ] Verificar que `index.html` tiene `<meta name="viewport" content="width=device-width, initial-scale=1.0, maximum-scale=1.0" />`
  - [ ] Corregir si usa valor diferente

- [ ] **T2 — NavMenu y AppBar responsive** (AC: 4)

  - [ ] Detectar breakpoint con `IBreakpointService` o usar clases CSS `d-none d-sm-block`
  - [ ] Asegurar que el botón hamburguesa del AppBar está visible en móvil (`d-sm-none`)
  - [ ] Cerrar el drawer automáticamente al navegar a otra página en móvil

- [ ] **T3 — KpgShiftForm responsive** (AC: 2)
  - [ ] Cambiar el grid de 2 columnas del formulario a 1 columna en pantallas `xs`
  - [ ] Verificar que `MudTimePicker` abre en modo `TimeEditMode.Normal` (rueda/reloj táctil) en móvil
  - [ ] Asegurar que los botones "Guardar AM" / "Guardar PM" son full-width en móvil

- [ ] **T4 — Tabla MisRegistros responsive** (AC: 3)

- [ ] **T5 — Dashboard cards responsive** (AC: 5)

- [ ] **T6 — Diálogos full-width en móvil** (AC: 6)

- [ ] **T7 — Prueba en dispositivos reales** (AC: 1–6)

  - [ ] Probar en iOS Safari (390px iPhone) — flujo de registro completo
  - [ ] Verificar con Chrome DevTools Device Toolbar los breakpoints xs (360), sm (414), md (768)

## Dev Notes

- MudBlazor usa breakpoints Bootstrap-compatibles: `xs` < 600px, `sm` 600–960px, `md` 960–1280px.
- `IBreakpointService` de MudBlazor permite detectar el breakpoint actual en C# para lógica condicional.
- `MudDrawer Variant="DrawerVariant.Temporary"` cierra el drawer al hacer clic fuera — comportamiento esperado en móvil.
- Para tablas de `MudDataGrid`, la solución más limpia es ocultar columnas con `HideSmallScreen="true"` si la versión de MudBlazor lo soporta, o con clases CSS `d-none d-md-table-cell`.
- El `KpgShiftForm` usa `MudGrid` internamente — cambiar `xs="12" sm="6"` en los `MudItem` aplica responsive automáticamente.
- No hay cambios al backend en esta story.
- Depende de: Story 9.1 completada (app instalable antes de optimizar la UX).
